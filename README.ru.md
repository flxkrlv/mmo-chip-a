# mmo-chip — analog-re-wip

> [**ENG**](README.md) | **RU**

**Форк [mmo-chip](https://github.com/giulioz/mmo-chip) для реверс-инжиниринга аналоговых и mixed-signal ИС.**  
Расширяет оригинальный цифровой CMOS-маршрут до **BJT, BiCMOS, резисторов, конденсаторов, диодов** — экстракция на уровне отдельных транзисторов с экспортом нетлиста SPICE/CDL/Spectre.

## Отличия этого форка ([lytex/mmo-chip](https://github.com/lytex/mmo-chip))

Этот форк следует за [flxkrlv/mmo-chip-a](https://github.com/flxkrlv/mmo-chip-a) (который сам является форком [giulioz/mmo-chip](https://github.com/giulioz/mmo-chip)) и добавляет поверх него следующее. Всё остальное в этом README относится ко всем трём.

### Большие изображения

- **Импорт пирамидальных TIFF** — кристаллы и overlay-изображения можно импортировать как пирамидальный / тайловый TIFF (libvips `tiffsave --pyramid`, SubIFD/OME-TIFF, SVS). Грубые уровни масштаба нарезаются из подходящего сохранённого разрешения, а тайлы полного разрешения декодируют только свою область, поэтому тайлинг огромных мозаик намного быстрее, чем из PNG.
- **Возобновляемый тайлинг** — фоновая генерация тайлов продолжается после перезапуска бэкенда, рендерит только отсутствующие на диске тайлы, а счётчик прогресса учитывает уже готовые (уже затайленный кристалл больше не «тайлится» заново).

### Неты и провода

- **Цвета нетов** — назначение цвета одному или нескольким нетам сразу из Outline Tree; переключатель меняет пользовательские цвета нетов на цвета по слоям, не теряя назначений.
- **Видимость отдельных нетов / ячеек** — скрытие отдельных нетов или ячеек при сохранении глобальных переключателей видимости.
- **Ширина нета для каждого кристалла** — ширина провода хранится для каждого кристалла, а не глобально.
- **Multi-wire (`B`) с несколькими поворотами** — шина прокладывается через несколько изгибов; разнесённые начальные точки заканчиваются на общем выровненном фронте.
- **Удержание для зума** — удерживайте указатель 2 с на нете (в дереве или на canvas), чтобы приблизиться к нему.
- **Окна по двойному клику** — двойной клик по нету открывает небольшое немодальное окно для переименования и выбора цвета (о повторяющихся именах предупреждает надпись прямо в окне); двойной клик по ячейке — окно для смены её типа и цвета типа. Эти окна (а также всплывающие окна floorplan и комментариев) можно перетаскивать; их положение запоминается и привязано к элементу при панорамировании и зуме.
- Переименование I/O-пинов двойным кликом прямо на canvas.
- **Прямоугольник выделения** держит начальный угол на кристалле при прокрутке или зуме во время перетаскивания и сам прокручивает вид у края canvas.
- Отключаемые крестики на вершинах нетов.

### Ячейки и I/O-точки

- **Маркеры изменения размера** — размер ячеек можно менять после размещения; изменение применяется ко всем ячейкам того же типа с корректными трансформациями.
- **Цвета типов ячеек** и тип ячейки при наведении.
- **Поворот / отражение в die viewer** — ПКМ по ячейке → *Rotate 90° clockwise*, *Flip horizontally*, *Flip vertically*. Рамка и содержимое поворачиваются вокруг центра рамки (высокая ячейка становится широкой на том же месте); если ячейка входит в выделение, действие применяется ко всему выделению; один шаг undo.
- **Перетаскиваемые I/O-точки** — I/O-точки всегда видны; их имена включаются переключателем.
- **Несколько пэдов на один пин** — скопируйте I/O-пэд (`Ctrl+C` или ПКМ → *Copy pad*) и вставьте (`Ctrl+V`), чтобы добавить ещё один пэд с тем же номером пина и именем в другом месте (например, два пэда VDD, разваренных на один пин). Пэды копируются вместе с выделенными ячейками и проводами. Переименование любого пэда переименовывает все пэды этого пина; *Apply to Die Viewer* на странице IC Package называет их все; нетлисты считают их одним портом.
- **Информация при наведении** — нижняя панель показывает сведения об объекте под курсором.

### Merge Cells

- **Multi overlay** — все ячейки одного типа накладываются в одно изображение, чтобы находить выбросы.
- **Повёрнутые ячейки показываются прямо** — каждый экземпляр вырезается по его реальному (ориентированному) контуру на кристалле и показывается в системе координат своего типа, поэтому повёрнутый экземпляр высокой ячейки тоже высокий. Flip H / Flip V / 90° действуют на то, что видно на экране; ручное и автоматическое выравнивание используют ту же систему, а при слиянии центр рамки ячейки остаётся на месте.
- **Линии растяжения** (`S`) — для точного совпадения проведите по кандидату вертикальную или горизонтальную линию, затем перетаскивайте линии (или края рамки), чтобы растянуть каждую полосу отдельно — кусочно-линейное растяжение по обеим осям. Над каждой полосой показан коэффициент (`×1.023`); двойной клик по линии удаляет её; *Reset stretch* убирает все. Каждое изменение — один шаг undo (`Ctrl+Z` / `Ctrl+Shift+Z`). Работает в режимах overlay, difference и candidate.
- Более быстрые миниатюры ячеек за счёт повторного использования тайлов die viewer.
- Исправлена история undo/redo.

### Floorplans

- **Редактирование геометрии после рисования** — прямоугольные и полигональные области можно перемещать и менять их форму после создания.
- **Undo/redo** для floorplan-областей (и для комментариев на топологии).
- Собственная палитра цветов и видимость отдельных областей в иерархии floorplan.
- `Esc` выходит из инструмента floorplan; первый клик уже ставит точку; `Space+H` переключает floorplans.

### Комментарии

- `✕` закрывает комментарий; кнопка-корзина удаляет его (только автор).
- Комментарии можно перетаскивать на новое место, а комментарии и ответы — редактировать и удалять их автору; всё отменяемо.

### Прочее

- **Редактируемые страницы кода** — сгенерированный нетлист на страницах Code / Analog Netlist можно править вручную и заново разбирать в схему.
- **Отключаемые линейки** — показ/скрытие линеек из Outline Tree.
- **Скриншоты высокого разрешения** — ПКМ по кнопке скриншота открывает ползунок разрешения, вплоть до полного разрешения тайлов кристалла (см. [Скриншот](#скриншот)).
- **Подсказки горячих клавиш** — во всплывающих подсказках кнопок, инструментов, вкладок и переключателей слоёв указана их горячая клавиша.
- Прокручиваемые всплывающие окна.
- Совместимость со старыми форматами `data/`.

## Поддерживаемые устройства

| Устройство | Детекция | Параметры |
|-----------|----------|-----------|
| **NMOS / PMOS** | Well-based через Clipper2 (разрезание diffusion по poly gate). Маркеры не нужны | W, L, fingers, M. Bulk: контакт на well → netId; нет → VDD/GND |
| **NPN** | Маркер `npn_id` + collector/base/emitter | AE (overlap base∩emitter), M |
| **PNP / LPnp** | Маркер `pnp_id` | AE, PE (периметр эмиттера), M |
| **Диод** | Маркер `diode_id` **или** NPN/PNP без коллектора | Площадь (AE из base-emitter overlap) |
| **Резистор** | Геометрически: тело (poly/base/emitter/hsr/film) → ME1 → контакты → PLUS/MINUS. Маркер не нужен | Ω или squares × Rₛ. Слои: poly-R, p-base, n+, HSR, thin film |
| **Конденсатор** | Маркер `cap_id` (overlap-область) | fF = площадь × плотность (не тестировалось) |

## Как рисовать устройства

Все слои рисуются в **Cell RE** соответствующим инструментом (rect/polygon/polyline).

### MOS

| Слой | Назначение |
|------|------------|
| `nwell` / `pwell` | Карман — nwell→PMOS, pwell→NMOS |
| `diffusion` | Область истока + стока |
| `polysilicon` | Затвор(ы), пересекающие diffusion |

1. Нарисуйте карман → diffusion внутри → polysilicon поперёк diffusion  
2. **Bulk:** `cont` на кармане **вне** diffusion/poly. Нет контакта → VDD (PMOS) / GND (NMOS)  
3. **Multi-finger:** Clipper2 разрезает diffusion между затворами → N отдельных MOS  
4. **Metal-connected D/S:** сток/исток, соединённые ME1 (или ME2+via) внутри ячейки, получают общий netId  

> Подробнее: [`docs/mos_detection.md`](docs/mos_detection.md)

### BJT

| Слой | Назначение |
|------|------------|
| `npn_id` / `pnp_id` | Bounding box |
| `collector` / `base` / `emitter` | Области прибора |

1. Нарисуйте bounding box → слои внутри → `cont` на каждом слое (терминалы сопоставляются автоматически)  
2. **Multi-emitter:** несколько эмиттеров → суммирование AE, M = количество  
3. **PNP/LPnp:** PE = периметр эмиттера (основной параметр)

### Диод

**Рекомендуется:** NPN/PNP без коллектора → автоматический диод. Base = анод, emitter = катод.

### Резистор

| Слой | Назначение |
|------|------------|
| `poly` / `base` / `emitter` / `hsr` / `film` | Тело (выберите один) |
| `contact` | Контакты (мин. 2) |

1. Выберите **body-слой** → рисуйте **polyline-инструментом** (`L`) — ортогональный snap, ширина в тулбаре (0–200 µm)  
2. Нарисуйте ME1, перекрывающий тело → поставьте 2+ контакта (станут PLUS/MINUS)  
3. Клик на любом сегменте → выделяется вся цепочка → ширина в правой панели  
4. Opacity-слайдер помогает выровнять ширину по изображению  

> **Sheet R₀:** настраивается в GUI (poly=25, hsr=1500, pb=200, npl=5, film=500 Ω/□)

### Конденсатор

Нарисуйте `cap_id` (bbox) — PLUS/MINUS оба на `contact`. Не тестировалось.

## Metal Stack (настраиваемая многослойная металлизация)

Die viewer поддерживает 1–6 слоёв металла (ME1–ME6) с соответствующими via (VIA12–VIA56).

### Настройка

**Net Settings** (шестерёнка рядом с "Nets") → **Metal layers** (1–6). Сохраняется per-project, перезагрузка не нужна. По умолчанию: 6 металлов.

| Элемент UI | Адаптация |
|------------|-----------|
| Палетры цветов слоёв | Только настроенные металлы |
| Чипы Wire/Via в тулбаре | Только настроенные металлы/via |
| Hotkeys 1..6 / Alt+1..5 | В пределах стека |
| E/Q via up/down | Берёт правильный via из стека |
| W cycle | Только по настроенным металлам |
| ProblemNavigator | Проверяет dangling via по правильной паре |

### Цвета слоёв

Настраиваются в Net Settings / Via Settings. Сохраняются per-project.

### Via labels

При zoom ≥ 8× каждая via показывает тип (VIA12, VIA56…) по центру — чёрная подложка, белый жирный текст. Включение: **VIA LABEL** в правой панели.

## Возможности Die Viewer

### Wire Tool

- **Переключение слоёв:** `W` активирует; повторно — цикл по стеку (ME1→…→ME6→ME1)  
- **Via (E/Q):** ставит via на конце превью (по умолчанию). Переключалка **Via: cursor / wire-end** в тулбаре  
- **Cross-layer snap:** провода разных металлов соединяются только через via-аннотацию  
- **AutoVia (checkbox):** при клике на вершине соседнего металла via ставится автоматически  
- **Via tool (O):** включает режим via; повторно — цикл по типам (VIA12→VIA23→…)  
- Контакты устройств подключаются только к **ME1** — ME2+ требует via

### ProblemNavigator

Панель проблем (`IssuesChip`): connectivity (неподключённые терминалы), wiring (обрывки), vias (dangling по паре металлов), I/O pins, overlaps, electrical warnings.

> [`docs/problem-navigator.md`](docs/problem-navigator.md) (на англ.)

### Операции с ячейками

| Действие | Как |
|----------|-----|
| **Copy / Paste** | `Ctrl+C` / `Ctrl+V` или ПКМ |
| **Make Unique** | `Shift+U` или ПКМ — отвязать ячейку от типа, редактировать независимо |
| **Поворот / отражение** | ПКМ по ячейке → Rotate 90° clockwise / Flip horizontally / Flip vertically (всё выделение, если ячейка выделена) |
| **Копирование I/O-пэдов** | Выделить пэды + `Ctrl+C` или ПКМ → Copy pad; `Ctrl+V` добавляет пэды с тем же номером пина и именем |
| **Cell Relationship** | **CELL REL** в правой панели — подсветка всех ячеек того же типа |

### Device Registry

Каждое устройство получает стабильный UUID из `kind + позиция + subType`. Переименования и оверрайды параметров сохраняются при переизвлечении и между сессиями.

### Слои (Cell RE)

| Слой | Группа |
|------|--------|
| `diffusion` / `polysilicon` / `nwell` / `pwell` | MOS |
| `collector` / `base` / `emitter` | BJT |
| `hsr` / `film` | Резисторы |
| `npn_id` / `pnp_id` / `res_id` / `cap_id` | Маркеры |
| `metal1`–`metal6` | Металлизация |
| `via1`–`via5` | Via-слои |
| `contact` | Контакты |

### Скриншот

`Ctrl+Shift+S` (или кнопка скачивания в SubBar) — экспорт текущего вида в PNG, композит всех overlay-слоёв включая analog device highlights.

**ПКМ по кнопке** открывает панель разрешения: ползунок от 0.5× до **native**-разрешения кристалла при текущем зуме (один пиксель результата на пиксель самого детального уровня тайлов, не меньше 4×), итоговый размер в пикселях и режим **Native**, который следует за зумом. Выбор запоминается. Более высокие значения заново рендерят вид и подгружают более детальные тайлы, поэтому добавляют реальные детали; изображение рендерится полосами и потоково записывается в PNG, так что может быть намного больше экрана (до 2 гигапикселей). Пока грузятся тайлы, показывается прогресс; долгий экспорт можно отменить. Наложенные поверх рисунки (analog highlights, комментарии) растягиваются из экранного разрешения.

### Поиск

`Ctrl+F` — фильтрация Outline Tree по имени net/cell. Enter фокусирует первое совпадение на canvas. Esc закрывает. Иконка поиска в заголовке "Items".

### Прочее

- **Net ID overlay:** имена нетов на die viewer (вкл. в боковой панели). VDD/GND скрыты  
- **Комментарии на топологии:** иконки с текстом, автором, ответами (WebSocket)
- **Панель горячих клавиш:** `Ctrl+/` — модальное окно со всеми шорткатами. Кнопка `?` в TopBar

## CV-детекция ячеек

Инструменты компьютерного зрения для автоматического обнаружения экземпляров ячеек. Доступны в правой панели (вкладка CV).

| Метод | Статус | Описание |
|-------|--------|----------|
| **Template matching** | Стабильный | Sobel-шаблонное сопоставление с референсным кропом. Основной рабочий метод детекции. |
| **AKAZE verify** | Опционально | Попарное сравнение найденных ячеек через AKAZE-кейпоинты. Ячейки ниже порога схожести удаляются. Фильтрация ложных срабатываний после template matching. |
| **Contour detection** | Экспериментальный | Детекция на основе контурных деревьев. Пока не работает стабильно. |

## Schematic Viewer

Принципиальные схемы уровня транзисторов из SPICE-нетлиста с **интерактивным канвасом** (движок по умолчанию).

- **Интерактив (по умолчанию)** — перетаскивание устройств, фиксация позиций (сохраняется), мультивыбор, поворот/зеркалирование символов, undo/redo
- **Иерархия** — floorplan-регионы как свернутые блоки с подписями портов; двойной клик / ПКМ по блоку — открыть его схему. Вкладки регионов (All, bandgap, …)
- **I/O pins** — пины и нетсы уровня кристалла
- ELK-раскладка (strategy/direction/compaction + настройка зазоров/рёбер в Netlist Settings), zoom колесом с Ctrl, тултипы имён нетов на проводах
- Экспорт: PNG, SVG (чёрно-белая)
- **Legacy static рендер** (netlist2svg, опционально): тумблер Static/Interactive, функциональная блок-диаграмма, кнопки pan/zoom, скачивание SVG/PNG/JSON

## LVS (Layout vs Schematic)

Сравнение извлечённого нетлиста из mmo-chip-a с нарисованной вручную схемой в стороннем САПР.

| Режим | Когда |
|-------|-------|
| **name-based** | Только если имена устройств совпадают (Q1, M2, R5…) |
| **vyges-lvs** | Name-independent сравнение топологии (netgen-подобный). |

Доступно на вкладке Analog Netlist (`Alt+4`).

## IC Package / Pin Planner

Сопоставление I/O-пинов кристалла с выводами корпуса по футпринту, сгенерированному через `@tscircuit/footprinter`.

Это инструмент для совмещения и разметки разварки, а не полноценное проектирование корпуса или механического посадочного места. Используются футпринты из библиотеки поддерживаемых корпусов; основной сценарий — сопоставить выводы корпуса с I/O-площадками кристалла.

- Выбор поддерживаемого футпринта с нумерованными выводами
- Переименование выводов корпуса непосредственно на canvas
- Поворот и зеркальное отражение кристалла относительно рамки корпуса
- Создание нескольких разварочных соединений между выводами корпуса и I/O-площадками кристалла
- Настройка ширины разварочного соединения, по умолчанию 30 µm
- Перенос имён из именованных соединений корпуса обратно в I/O-пины кристалла
- Экспорт вида совмещения в PNG и таблицы выводов в CSV

| Клавиша | Действие |
|---------|----------|
| `S` | Pan / zoom |
| `T` | Переименовать вывод корпуса |
| `W` | Создать разварочное соединение |

## LLM-анализ

Опциональный AI Assistant анализирует извлечённый netlist и создаёт ранжированные карточки предположений о возможной функции схемы, роли устройств или подозрительных подключениях. Карточки содержат уровень уверенности, reasoning, подтверждающие признаки, затронутые устройства и предлагаемые проверки. Перед созданием интерактивной карточки проверяются существование устройств и связность фрагмента через net; это не доказывает электрическую функцию.

Ассистент работает в режиме read-only. Предположения можно показать на кристалле, открыть в Net Graph и посмотреть как фрагмент netlist или schematic.

Во время обсуждения карточки модель может использовать управляемые tool calls, если они включены:

- **`mmochip_lvs_check`** — сравнить candidate subcircuit с reference LVS library `analog-circuits-sky130` по топологии. Активную библиотеку можно выбрать, а пользователь может добавить собственные reference cells из SPICE/Spectre subcircuit.
- **`mmochip_vision`** — запросить фрагменты кристалла и overlay layers для мультимодальных моделей, чтобы проверить геометрию устройств и подключение терминалов.
- **`mmochip_spice_sim`** — запустить серверную проверку гипотезы через ngspice и вернуть измерения симуляции. Инструмент экспериментальный и требует дальнейшего тестирования.
- **`mmochip_card_update`** — предложить структурированное обновление существующей карточки предположения.

Доступ к инструментам явно управляется пользователем. Модель предлагает предположения и признаки, а пользователь просматривает и проверяет результат.

### Ruler tool

Нажмите `K` и проведите линию по кристаллу. По умолчанию измерение строится ортогонально. Можно создать несколько рулеток: `S` выбирает рулетку, `Shift+click` выбирает несколько, а клик по пустому месту снимает выделение. `Delete` удаляет выбранные рулетки, `Shift+K` — все рулетки.

Масштаб задаётся через double-click или ПКМ → **Set scale from ruler**. После задания масштаба длина отображается в µm, а значения меньше 1 µm — в nm. При zoom меньше 20% неактивные рулетки скрываются, текущая и выбранная остаются видимыми.
