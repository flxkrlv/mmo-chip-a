## Rotated cells: die-viewer rotate/flip + Merge shows instances in the type frame
- User: tall cell type pasted near a rotated (wide) instance; Merge showed it wide. Cause: crop = type box at (x,y) (not the real oriented footprint) and MergeCanvas drew it FORWARD-oriented, while die convention is die = M·type (M = R(θ)·F about type-box centre).
- New convention everywhere: crop = cellWorldRect (backend tiles.ts cellDieRect, mirror of the frontend helper); display = M⁻¹·crop via lib/cellFootprint.dieToTypeMatrix (+ exported unorient); lib/cellCrop.drawCellCrop used by MergeCanvas (single/sxs/multi) and CellRECanvas (image + die overlay). cellCropUrl adds &o=<rot><h><v> and &b= for browser cache busting.
- Merge buttons act on the shown view: lib/mergeCells.orientInTypeFrame (flip = toggle flag; rotate CW = θ−90, or θ+90 when exactly one mirror). Drag-align delta = −M·Δ. viaAlign uses unorient + −M·t; auto-align aligns type boxes by centre. buildMergeAction keeps the type-box centre (x += (candW−specW)/2) — test updated.
- Die viewer: right-click a cell → Rotate 90° CW / Flip H / Flip V (orientOnDie: rot θ+90; flip → θ negated + flag), applies to the selection when the clicked cell is selected; one undo; disabled when cells locked. Footprint turns about its centre.
- Heads-up: cells merged earlier with 90/270 (old inverted convention) may now show rotated 180° in Merge; re-rotate them.
- tests: lib/cellOrient.test.ts (operators vs matrices, all 8 orientations). Frontend tsc clean, 242/242; backend tsc clean. Not browser-verified. Not committed.
