## MCP server global to all dies, per-die manual approval
- Request: one MCP server for every die, but a die no client used before needs manual approval.
- Endpoint: POST /mcp (global). tools/list = list_dies + every tool with a required `dieId` arg injected (withDieIdArgument in api/mcp.ts; tool modules unchanged, dieId stripped before callMcpTool). GLOBAL_INSTRUCTIONS mention list_dies + approval. Old POST /mcp/:dieId kept (bound die, no dieId arg), same access gate.
- backend/src/mcp/mcpAccess.ts: <dataRoot>/mcp-access.json {dies: {id: {state pending|approved|denied, at, clientName}}}, per-dataRoot promise lock, atomic write (tmp + rename). Migration when the file is missing: dies that already have an mcp.json (used / configured under the per-die endpoint) start approved.
- Gate (checkAccess): first call on a die with no entry → pending + WS broadcast; call is held up to approvalWaitMs (default 50 s, createApp `mcpApprovalWaitMs`) via waitForDecision (EventEmitter + re-check after subscribe); then approved → runs, else tool error (pending: "ask the user to approve"; denied: refused immediately). Decisions stick.
- GUI routes: GET /api/mcp/access (auth-protected, entries for existing dies), PUT /api/mcp/access/:dieId {state approved|denied}. GET /api/dies/:id/mcp now has `access` and endpointPath "/mcp".
- ws.ts: emitMcpAccess() → { type: "mcp/access" } to every socket.
- Frontend: components/McpAccessPrompt.tsx (fixed bottom-right card per pending die: Approve / Deny), mounted in AuthGate; api/mcp.ts getMcpAccess/setMcpAccess/useMcpAccess (subscribeGlobal + 30 s poll). McpPanel: endpoint labelled "all dies", new "MCP access to this die" section (Approve in advance / Approve / Deny / Revoke).
- mcpb manifest 0.4.0 (display name "mmo-chip", list_dies, endpoint hint /mcp), tools/README updated, dist/mmo-chip.mcpb rebuilt. Must reinstall in Claude Desktop and change the endpoint to /mcp to get multi-die.
- Tests: mcp.test.ts 8/8 (new global-endpoint test: schema, list_dies, missing/unknown die, pending timeout, approve while waiting, deny incl. legacy endpoint, 400 on bad state; harness approves its die). Backend 67/72: the 4 known assistant/LVS failures + overlay pyramidal TIFF, which passes alone on both trees (flaky under load; an mcp test also once hit an ENOTEMPTY temp cleanup race). Frontend tsc clean, 288/288. Not browser-verified, not tried with a real client. Not committed.
- Caveat: approval is a GUI action guarded by the same JWT the MCP client holds, so a client with shell access + the token could call PUT /api/mcp/access itself; MCP tools alone cannot.

## Claude Desktop extension died right after initialize with the /mcp endpoint
- Symptom (Claude Desktop log): "initialize" sent, server transport closed ~50 ms later, "Server disconnected" (the "server/discover probe" lines are Desktop's version probing and fall back to legacy — noise).
- Cause: tools/mcpb/server/index.js validated MMO_CHIP_MCP_URL against /mcp/<dieId> only and process.exit(1) otherwise — I'd switched the docs/manifest to /mcp but missed the bridge.
- Fix: accept /mcp or /mcp/<dieId>; a bad URL no longer exits, it's returned as a JSON-RPC error on every request (visible in the client). Manifest 0.4.1, dist/mmo-chip.mcpb rebuilt.
- Smoke-tested the bridge against the running backend on :3001 with /mcp: reaches the new route (401 without token → readable "set the login token" error); bad URL → readable error. Full round trip with a token not tried by me. Lesson: when changing an endpoint shape, grep every client (bridge, manifest, panel, docs) for the old pattern.
