# 2026-06-22 — Project export/import, rename, per-die overlays

## Коммиты

ac1e40b — project export/import (light+full), rename, per-die overlay storage

## Новая функциональность

### Project Export/Import
- **`POST /api/dies/:dieId/export-project`** — два режима:
  - `light`: metadata.json + annotations.json + spice_config.json + export/ (нетлисты) + preferences.json (опционально)
  - `full`: light + original/ (die-фото) + overlay-images/ (все оверлеи проекта)
  - Пишет во временный файл, отдаёт через `response.download()` — надёжнее Express v5 streaming
- **`POST /api/dies/import-project`** — принимает ZIP, восстанавливает die
  - `409 die_already_exists` — если dieId занят
  - `?name=XXX` — импорт под новым именем с новым dieId
  - **Auto-suffix** при совпадении human-readable имени: `project (2)`, `project (3)`
  - Ресторит оригинальную картинку и оверлеи, фиксит `originalPath`
  - Preferences возвращает фронтенду → тот пишет в localStorage

### Rename (GUI)
- **`PUT /api/dies/:dieId/rename`** — обновляет `name` в metadata.json
- ThumbCard kebab menu: Rename, Export (light), Export (full), Delete
- При экспорте confirm: включить preferences из localStorage?

### Per-die overlay storage
- **Изолированы** от глобальной кучи: `data/overlay-images/{dieId}/`
- Маршруты: `/api/dies/:dieId/overlay-images/list|:filename|upload`
- Старые файлы в `data/overlay-images/` (плоская структура) — при старте сервера warning
- Надо перенести вручную в `data/overlay-images/{dieId}/`

## Баги

- **Rename не работал** — в `dies.ts` не импортирован `apiPut` → ReferenceError на `renameDie`. Починено
- **Full export висел** — двойная проблема:
  1. `archive.finalize()` внутри `buildExport`, pipe после — данные терялись.
     Фикс: разделил на `queueExport` (только постановка) + finalize в хендлере с записью в temp file
  2. `zlib: { level: 6 }` на already-compressed JPEG.
     Фикс: `level: 0` (store mode)
- **Base image после импорта не грузилась** — `originalPath` в metadata.json вёл на старую машину.
  Фикс: ресторим картинку → запоминаем новый путь → только потом пишем metadata.json + верификация
- **Два проекта с одним названием** — добавлена проверка имени при импорте, автосуффикс

## Архитектурные решения

- Export → temp file на диск → `response.download()` вместо `archive.pipe(response)` (Express v5 streaming issues)
- `zlib: { level: 0 }` — JPEG/PNG уже сжаты, zlib бесполезен
- Overlay images: per-die директория, а не глобальная плоская (изоляция проектов)
- Import: вскрытие ZIP в память через `adm-zip` (для гигабайтных проектов — переделать на стримы)

# 2026-06-22 — Multiplayer: Auth + Presence (Phase 1.1 & 1.3)

## Обсуждение и решение
- Обсудили мультиплеерные фичи для chip reverse engineering: логин, мышки (Figma-style), floorplan, текстовые аннотации, чат
- Решили делать в порядке: логин → кто онлайн → floorplan → комментарии на топологии → (потом) мышки + чат
- Логин — foundation для всего остального

## План (PLAN.md полностью переписан)
- **Phase 1.1** (5-6д): JWT-аутентикация (bcrypt+jsonwebtoken), WS-auth, "кто онлайн"
- **Phase 1.2** (1д): Production build (Express раздаёт статику) — отложен до Phase 3
- **Phase 1.3** (2д): WS presence (online/offline/status)
- **Phase 2.1** (4д): Floorplan (rect/poly + label + reservedBy — предупреждение, не блокировка)
- **Phase 2.2** (3д): Комментарии на топологии (пин + popover)
- **Phase 3** (4-6д): Caddy + HTTPS + Docker + OAuth
- **Phase 4** (4-5д): Figma-style cursors (отложено)

## Реализовано

### Backend — Auth Infrastructure
- **Новый файл:** `backend/src/api/auth.ts` — register/login/verify endpoints
- **Новый файл:** `backend/src/auth/middleware.ts` — JWT middleware (signToken, verifyToken, requireAuth, optionalAuth, extractWsToken, isAuthEnabled)
- **Auth включает только при `JWT_SECRET`** env var. Без неё — dev mode, все запросы проходят без аутентикации
- **JWT payload:** `{ userId, username }`, expires in 7 дней
- **Storage:** `data/users.json` — простой JSON-файл с массивом пользователей
- **User CRUD:** createUser, findUserByUsername, findUserById — добавлены в `store.ts`
- **WS auth:** token в query string `?token=<jwt>`, закрывает сокет при невалидном

### Backend — Auth на роуты
- `app.ts`: middleware проверяет `req.path` — `/auth/*` и `/health/*` публичные, всё остальное под auth
- `GET /api/dies/*` — публичные (тайлы, изображения грузятся через `<img>` без Bearer)
- Mutation (POST/PUT/DELETE) — под auth

### Backend — WS Presence
- **Типы сообщений:** `user/online`, `user/offline`, `user/status`, `user/list`
- При коннекте: broadcast `user/online` всем + `user/list` самому юзеру
- При дисконнекте: broadcast `user/offline`
- При `status` сообщении: запоминаем `dieId` + `tool`, broadcast
- `getOnlineUsers()` — для API

### Frontend — Auth
- **`frontend/src/state/auth.ts`** — Zustand store + persist в localStorage
- **`frontend/src/api/auth.ts`** — register(), login(), verify()
- **`frontend/src/api/client.ts`** — Bearer token во всех запросах
- **`frontend/src/routes/LoginPage.tsx`** — форма логина/регистрации, тёмная тема, BrandMark
- **App.tsx:** AuthGate-обёртка на всех роутах, PublicRoute для /login
- **TopBar.tsx:** username + аватарка + logout + OnlineUsersPanel
- **Logout:** очистка localStorage, редирект на /login

### Frontend — WS Presence
- **`frontend/src/api/annotationsWebSocket.ts`** — token в URL WS, `subscribePresence()` для глобальных presence-событий, `sendStatus()` для отправки статуса
- **`frontend/src/state/onlineUsers.ts`** — Zustand store для списка онлайн-пользователей
- **`frontend/src/components/shell/OnlineUsersPanel.tsx`** — аватарки с цветами (hash от userId), зелёная точка если на die, серая если в библиотеке
- **`frontend/src/lib/useUserStatus.ts`** — хуки useUserStatus(dieId, tool) и usePageStatus(dieId) с debounce
- **DieViewerPage.tsx** — useUserStatus(dieId, activeTool)
- **LibraryPage.tsx** — usePageStatus(null)

### Ws connection timing fix
- WS коннектится **только после** AuthGate, чтобы в production (c JWT_SECRET) не слать запросы без токена
- В dev mode (без JWT_SECRET) — auth disabled, WS коннектится сразу

### LoginPage dark theme styling
- Обёрнут в `.dark` класс
- Brand-бар MMO·CHIP сверху
- Инпуты через className="input"
- Кнопка с className="btn accent"

## Баги (пофиксены в этой сессии)

1. **Frontend показывал логин без JWT_SECRET** — AuthGate проверял token в localStorage, которого нет. Фикс: добавил `GET /api/auth/status`, проверяет `isAuthEnabled()` на старте
2. **Тайлы не грузились с JWT_SECRET** — `<img>` теги не шлют Bearer. Фикс: все GET-запросы к `/api/dies/*` публичные (без auth)
3. **WS падал до логина** — `usePresenceWebSocket()` вызывался до AuthGate. Фикс: перенёс вызов внутрь AuthGate
4. **После перезагрузки список онлайн неполный** — сервер не слал текущий список новому юзеру. Фикс: `user/list` при коннекте, `user/online` не себе
5. **ML sidecar не стартует на Windows** — unix-path в `package.json`. Предсуществующая проблема, не связана с моими изменениями

## Архитектурные решения

- Token в **localStorage** (не cookies) — нет CSRF, SameSite, HTTPS-only. Работает и в LAN, и в Web
- **Auth опциональна:** `JWT_SECRET` env var включает/выключает. Без неё — dev mode, всё работает как раньше
- **GET-запросы к /api/dies/* публичные** — тайлы/изображения грузятся через `<img>` без Bearer
- **userId нигде не сохраняется в аннотациях пока** — будет добавлено в Phase 2 (floorplan, comments)
- **WS-протокол расширен** — новый тип `presence` / `user/list` / `user/online` / `user/offline` / `user/status`
- Пароли — bcryptjs (pure JS, без native binding проблем на Windows)
- JWT dev fallback: `"mmo-chip-dev-secret-do-not-use-in-production"` с warning в консоль
