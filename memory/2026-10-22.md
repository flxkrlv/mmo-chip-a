# 2026-10-22

## SPICE handoff round 4 — "Go to SPICE results" restores the whole page

**Task:** after the handoff from the card-dialog agent run, the SPICE Simulation
page must be fully configured — the right models selected, the agent's real
directives in the ngspice directives field, the real testbench — so the user can
just press Run and get the SAME result the agent got, edit the testbench, and
use the Agent on the SPICE tab to refine the tb the agent created.

### The five gaps that were there

1. `directives` was never set on handoff — the field kept whatever was in
   localStorage for that die/subcircuit.
2. `modelSelection` / `customModels` were never set — the models were baked
   into the netlist text only, so the picker disagreed with the netlist.
3. `netlistOverride` was set to the backend's raw run netlist, including the
   `.control` block (`save` / `run` / `write sim.raw` / `quit`) and the trailing
   `.end`. `sanitizeNetlistForRun` keeps `.control` verbatim, so pressing Run in
   the simulator would have executed a second `run` and `quit` out from under
   the worker.
4. With an override active, `setDirectives` was a no-op — the SPICE-tab agent's
   edits never reached Run.
5. `.control`/`.end` leaked into the testbench view netlist.

### The design that fixed them

Do NOT keep the agent's netlist as an override. Decompose the handoff and feed
each piece back into the page's own state:

- `dut` — models + DUT as actually simulated → new `handedDut` state, used for
  `dutNetlist` only while the selected subcircuit still matches the handed DUT
  name (or nothing is selected). Picking a different subcircuit reverts to the
  page's own DUT, no extra wiring needed.
- `directives` — the testbench with `stripRunScaffolding` applied (drops the
  runner's `.control` and the trailing `.end`; keeps `.print`, `.save`,
  `.measure`, sources, analysis). Safe because `save` only limits what is
  *written* to the raw file — the solver computes everything — and round 3
  already filters traces client-side.
- `modelCards` / `modelSelection` / `customModels` — new `optionForCard` +
  `restoreModelSelection` in `shared/src/spiceModels.ts` match the cards back
  against the library, so the picker's radio buttons move to what was simulated
  and unmatched cards stay as the user's own.

`splitAtSectionMarker` in `shared/src/spiceNetlist.ts` does the split on the
section marker (`* ── Testbench ──` from the backend, `* ── Directives ──` from
the composer) and returns `dut: null` when there is no marker — guessing would
duplicate the testbench on recompose.

Auto-run switched from a string compare (`pendingHandoffRun`) to a nonce:
the handoff effect queues `pendingHandoff`, a second effect declared after
`useDirectives` lands it in page state (a render must happen in between, because
the directives hook reloads itself from storage whenever the subcircuit changes
and would otherwise wipe the agent's testbench a moment later), and it bumps the
nonce. By the time the nonce effect runs, `runRef` holds the recomposed netlist.

`useSpiceAgent.buildSimNetlist` now emits `* ── Directives ──` and splits with
the shared `splitAtSectionMarker` instead of its own `extractDutOnly` regex,
which did not recognise `* ── Testbench ──` — with a handoff active that let
the testbench leak into the "DUT" and get appended a second time.

`stripModelCards` also drops a `* ── Models ──` label now, so a netlist that has
been composed once does not come back with two of them.

### Verified empirically — `.tools/agent-probe/reproduce-probe.mts`

Real LM2937 (86 devices, 7 pins), `.dc VDD 3 7 0.25` + two `.measure`s, run
through `executeSpiceSimTool`, then decomposed with `handoffSections` and
recomposed exactly the way the page does it, then run again:

| path | agent | page after handoff |
| --- | --- | --- |
| DUT's own cards | vref 0.984644, vout 0.218694 | vref 0.984644, vout 0.218694 |
| library cards by id | vref 1.02851, vout 0.0363384 | vref 1.02851, vout 0.0363384 |

REPRODUCIBLE: true. With library cards the picker restores to
`{"diode":"diode-generic","npn":"npn-gp","pnp":"pnp-gp"}` and no cards are left
over as "own". The recomposed netlist has no `.control`, no `.end`, and exactly
one `── Models ──` label.

### Backend prompt

`/assistant/spice-chat` system prompt now says: when the netlist already contains
a testbench, that testbench is what you are being asked to change — edit it in
place, do not start over, never output it twice. Without that the model treated
the handed-over tb as context and rewrote from scratch.

### Notes / gotchas

- `useModelSelection` returns `{ selection, setSelection, select }` — the page
  only destructured two of them; `setSelection` is needed to restore.
- `autoInstantiateDut` inserts `X1` at the first top-level device line, i.e.
  inside the testbench section, and uses the DUT's own port names as net names.
  That is why the handed `directives` field legitimately contains the
  `* -- DUT instantiated --` comment plus the X1 line.
- Probe gotcha: a testbench that names its source `VDD` but sweeps `VCC` fails
  with "Voltage source ... named 'vcc' is not in the circuit" — ngspice sweeps
  the *source*, not the net.
- The working tree still carries the user's own items untouched:

  `docs/SPICEVISION_RE_ANALYSIS.md`, `docs/compare/`, `docs/spicevision/`,
