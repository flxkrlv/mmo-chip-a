3. **Тест-бенч всегда блоком** — раньше DUT-блок рисовался только когда выбран

   оборачивает плоский DUT в `.subckt` с выведенными пинами (`wrapFlatDut`:
   пин = узел, который трогает тест-бенч) и инстанцирует DUT, если его никто
   не инстанцировал (`autoInstantiateDut`). Рендер — тот же
   `InteractiveAnalogSchematic` + `HierarchyBlock` (ELK проверено: 7 пинов,
   3 провода, якоря пинов).
4. **«Go to SPICE results» не открывал результаты** — разобрался по цепочке:
   - `.op` даёт ОДНУ точку → `parseWaveforms` возвращал `[]` → пустой график.

     (Measurements + Operating point) вместо пустого графика.
   - `useSpiceAgent` считал `waveforms.length === 0` ошибкой → каждый `.op`
     прокручивался до исчерпания ретраев. Теперь `.op` с данными — успех.
   - Авто-запуск после handoff гонялся через `setTimeout` и мог выполниться
     ДО того, как state с netlist долетал → запускался старый netlist. Сделал
     детерминированный цикл: `pendingHandoffRun` + effect по `effectiveNetlist`.
   - Handoff теперь сам выбирает DUT-сабконтур (`detectDutName`), а не оставляет
     «всю схему».
5. **Директивы по умолчанию убрал** — пример «inverter» был мёртвым грузом и

## SPICE: правки по фидбэку (третий раунд)

Три пункта:

### 1. Вкладка Testbench часто рисует ВСЮ схему

Причина: `SpiceSimulationPage` передавал в `TestbenchSchematic` целиком
`effectiveNetlist`. Для плоского netlist'а (как его пишет backend-тул)
`parseTestbenchNetlist` попадал в ветку «нет `.subckt` → рисуй всё» →
картинка всего чипа вместо тест-бенча.

Стало: страница собирает netlist **только для вида** —
`splitSimulationSections` (маркер `* ── Testbench ──` / `* ── Directives ──`,
иначе структура, иначе fallback) + `buildTestbenchViewNetlist`, который
выдаёт пустой `.subckt NAME ports` / `.ends` + инстанс + элементы тест-бенча.
Тело DUT физически не попадает в netlist вида — нарисовать его нечем.
Если тест-бенч уже инстанцирует DUT, его собственная строка `X…`
используется как есть (сохраняет написание узлов самого тест-бенча);
если инстанса нет — генерируется `X<n> ports name` (имя не конфликтует).

Проверка на реальном `lm2937_bandgap.cir` (≈200 устройств): вид = 1 блок,
7 пинов, девайсы только `VDD, RLOAD`.

### 2. Графиков очень много при `.print (vref)`

Причины две: backend писал в raw ВСЕ векторы, а фронтенд их не фильтровал.

- backend: `assembleNetlist` теперь добавляет `save <signals>` ВНУТРИ
  `.control` перед `run`. `save` берётся из `requestedSignals` — `.print`,
  `.save`, `.plot`, `.measure` и команды `print`/`save`/`plot` внутри
  `.control`. Важно: сигналы читаются из `converted.netlist` ДО
  `flattenControlBlocks` (иначе `save` из `.control` теряется) и ДО
  выноса `.measure op` (иначе теряются их векторы).
- frontend: `runFullSimulation` фильтрует трейсы по `requestedSignals`
  через `requestedSignalKeys` (запрос) / `vectorKeys` (измеренный вектор).
  Если фильтр не матчит НИЧЕГО — это опечатка в написании, а не просьба
  показать пустоту: возвращается всё. UI показывает «showing N of M traces»
  + кнопку «show all», полный список лежит в `output.allWaveforms`.

Матчинг: `v(`/`i(` — точные (запрос тока питания не тянет напряжение),
голое имя — свободное (`ref` ↔ `v(ref)`, `vref` → `ref`), одна обёртка
скобок: `.print (vref)`.

Проверка ngspice-47 (важное, проверено руками):
- `save` ДО `run` внутри `.control` реально ограничивает raw (и на `.dc`,
  и на `.tran`); ось развёртки (`v(v-sweep)`, `time`) сохраняется всегда.
- `.measure` падает, если его вектор не сохранён → список `save` должен
  быть объединением `.print`/`.save`/`.measure`.
- `save` с неизвестным вектором молча игнорируется → можно запрашивать
  «с запасом», ничего не ломается.
- `save` строкой НА ВНЕШНЕМ уровне (вне `.control`) невалиден — ngspice
  ругается «Error on line».
Проверка на том же LM2937: `.print dc v(ref) v(out)` → в raw ровно
3 вектора (`v(v-sweep)`, `v(out)`, `v(ref)`) вместо ~200 внутренних узлов.

### 3. Кнопку переключения правой панели — в правый край страницы

`<PanelToggle side="right">` был внутри `children` `SubBar`, т.е. посреди
тулбара. Перенёс в слот `<SubBar right={…}>`. Попутно убрал inline
`<div style={{flex:1}}/>` — с двумя спейсерами группа кнопок вставала бы
посередине; статус и кнопки теперь один кластер слева, тумблер — у края.
