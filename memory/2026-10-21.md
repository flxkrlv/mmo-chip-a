## SPICE: правки по фидбэку (третий раунд)

Три пункта:

### 1. Вкладка Testbench часто рисует ВСЮ схему

Причина: `SpiceSimulationPage` передавал в `TestbenchSchematic` целиком
`effectiveNetlist`. Для плоского netlist'а (как его пишет backend-тул)
`parseTestbenchNetlist` попадал в ветку «нет `.subckt` → рисуй всё» →
картинка всего чипа вместо тест-бенча.

Стало: страница собирает netlist **только для вида** —
`splitSimulationSections` (маркер `* ── Testbench ──` / `* ── Directives ──`,
иначе структура, иначе fallback) + `buildTestbenchViewNetlist`, который
выдаёт пустой `.subckt NAME ports` / `.ends` + инстанс + элементы тест-бенча.
Тело DUT физически не попадает в netlist вида — нарисовать его нечем.
Если тест-бенч уже инстанцирует DUT, его собственная строка `X…`
используется как есть (сохраняет написание узлов самого тест-бенча);
если инстанса нет — генерируется `X<n> ports name` (имя не конфликтует).

Проверка на реальном `lm2937_bandgap.cir` (≈200 устройств): вид = 1 блок,
7 пинов, девайсы только `VDD, RLOAD`.

### 2. Графиков очень много при `.print (vref)`

Причины две: backend писал в raw ВСЕ векторы, а фронтенд их не фильтровал.

- backend: `assembleNetlist` теперь добавляет `save <signals>` ВНУТРИ
  `.control` перед `run`. `save` берётся из `requestedSignals` — `.print`,
  `.save`, `.plot`, `.measure` и команды `print`/`save`/`plot` внутри
  `.control`. Важно: сигналы читаются из `converted.netlist` ДО
  `flattenControlBlocks` (иначе `save` из `.control` теряется) и ДО
  выноса `.measure op` (иначе теряются их векторы).
- frontend: `runFullSimulation` фильтрует трейсы по `requestedSignals`
  через `requestedSignalKeys` (запрос) / `vectorKeys` (измеренный вектор).
  Если фильтр не матчит НИЧЕГО — это опечатка в написании, а не просьба
  показать пустоту: возвращается всё. UI показывает «showing N of M traces»
  + кнопку «show all», полный список лежит в `output.allWaveforms`.

Матчинг: `v(`/`i(` — точные (запрос тока питания не тянет напряжение),
голое имя — свободное (`ref` ↔ `v(ref)`, `vref` → `ref`), одна обёртка
скобок: `.print (vref)`.

Проверка ngspice-47 (важное, проверено руками):
- `save` ДО `run` внутри `.control` реально ограничивает raw (и на `.dc`,
  и на `.tran`); ось развёртки (`v(v-sweep)`, `time`) сохраняется всегда.
- `.measure` падает, если его вектор не сохранён → список `save` должен
  быть объединением `.print`/`.save`/`.measure`.
- `save` с неизвестным вектором молча игнорируется → можно запрашивать
  «с запасом», ничего не ломается.
- `save` строкой НА ВНЕШНЕМ уровне (вне `.control`) невалиден — ngspice
  ругается «Error on line».
Проверка на том же LM2937: `.print dc v(ref) v(out)` → в raw ровно
3 вектора (`v(v-sweep)`, `v(out)`, `v(ref)`) вместо ~200 внутренних узлов.

### 3. Кнопку переключения правой панели — в правый край страницы

`<PanelToggle side="right">` был внутри `children` `SubBar`, т.е. посреди
тулбара. Перенёс в слот `<SubBar right={…}>`. Попутно убрал inline
`<div style={{flex:1}}/>` — с двумя спейсерами группа кнопок вставала бы
посередине; статус и кнопки теперь один кластер слева, тумблер — у края.

## Удельная емкость (fF/мкм²) — редактируется в Settings, считает емкость конденсаторов

Задача: в GUI редактируемая удельная емкость на единицу площади; емкость
конденсатора = площадь × удельная емкость; это значение уходит в SPICE-нетлист;
персист как у резисторов (sheetR); редактирование в SettingsPanel.

### Как сделано (по образцу резисторов)

- `frontend/src/lib/export/capacitorDefaults.ts` (новый) — зеркало
  `resistorDefaults.ts`: `DEFAULT_CAP_DENSITY = 1` [fF/мкм²],
  `effectiveCapDensity(user)` (битое/нулевое значение → дефолт),
  `effectiveCapacitance(geom, density, overridden)` → **C = area_um2 × density**.
- `usePreferences.capDensity` + `setCapDensity` — персистится в localStorage
  (`partialize`) рядом с `sheetR`.
- `SpiceConfig.capDensity_fF_um2` (shared/src/types.ts) — число доезжает до
  генераторов нетлиста. Старое неиспользуемое поле `capDensity_fF: Record`
  (per layer pair) убрано, чтобы не путать два похожих имени.
- `CapDensityConfigPanel.tsx` (новый) — поле ввода fF/мкм², рендерится в
  SettingsPanel → "RE Cell Settings" под `SheetRConfigPanel`.
- `AnalogNetlistPage` / `SpiceSimulationPage` — кладут `capDensity_fF_um2`
  в SpiceConfig; значение ещё и пишется в per-die `spice_config.json`
  (как sheetR) и при загрузке сеет глобальную настройку, если та ещё дефолт.

### Где считается емкость

Значение **производное** — ровно как сопротивление у резистора (squares ×
sheetR), поэтому оно считается там, где пишется нетлист, а извлечённая
геометрия хранит «сырую» площадь пластины:

- `lib/export/spice.ts` → `fmtCap(geom, config, overridden)` → `c=…f`
  (CDL / Spectre / HSPICE, плоский и иерархический).
- `lib/schematic/spiceTSFormat.ts` → spice-ts нетлист (fF → F).
- `lib/simulation/findingsToSubcircuits.ts` → AI-подсхемы симуляции.
- Показ: DeviceInspector, DeviceInstancePanel, AnalogDeviceHighlights (канвас
  дие-вьюера), cellRE: AnalogDeviceLayer, AnalogDeviceInspector, CellRERightPanel.
- `api/assistantAnalysis.ts` → `snapshotGeometry()`: снапшот, который уходит
  на бэкенд, несёт вычисленную емкость, поэтому DUT-нетлист ассистента тоже
  верный.

**Правило приоритета:** если ёмкость зафиксирована руками в Cell RE
(override `capacitance_fF` в device registry) — побеждает ручное значение;
иначе C = площадь × удельная емкость. Флаг override живёт в
`_overriddenParams`.

### Доработка: графический вид схемы тоже показывал старую емкость

Пользователь заметил, что на схеме (netlist2svg / интерактивная схема / блок-диаграмма)
емкость осталась старой: эти рендереры брали `geometry.capacitance_fF` (дефолт 1 fF/мкм²).

Сделано так же, как для нетлиста — значения technology передаются в рендерер:

- `netlist2svgFormat.ts` — новый тип `SchematicValues { capDensity?, sheetR? }`;
  `valueString(d, values)` и `deviceAttributes(d, values)` считают
  **C = area × density** и **R = squares × sheetR**; `Netlist2SvgConfig` получил
  `capDensity_fF_um2` и `sheetR_ohms`.
- `blockDiagramFormat.ts` — то же для функциональной блок-диаграммы
  (`BlockDiagramConfig` + `unassignedAttrs(d, values)`).
- `interactiveSymbols.ts` — `labelForSpec(spec, d, key, values)` для подписей
  интерактивной схемы.
- Вызовы: `SchematicViewPanel` (5 мест), `CellAnalogSchematicCanvas`,
  `RECellPage` (spiceConfig схемы cell RE теперь с удельной емкостью и sheetR),
  `AssistantPanel` (фрагмент находки), `InteractiveAnalogSchematic` (DeviceNode
  подписан на preferences).

Побочный эффект: на схеме теперь и сопротивление считается по текущему sheetR
(раньше показывалось значение, посчитанное при извлечении с дефолтом) — так
схема совпадает с нетлистом.

Тест: `capacitorDefaults.test.ts` — 6 тестов (добавлен кейс на подпись схемы:
`200pF` при density 2 и площади 100 мкм²).

## AI-ассистент: память обсуждения по карточкам (Discuss)

Задача: 502 «LLM returned empty content», модель «забывает» прошлый контекст и
повторяет те же ошибки; хочется, чтобы задавала уточняющие вопросы и
итерировала с учётом прошлых ошибок.

### Диагноз (обсуждение по карточке, не analyze)

1. **История передавалась, но была пустой по сути.**
   - Результаты инструментов писались в тред с `content: ""`, а бэкенд мапил
     только `{role, content}` → модель видела пустые реплики ассистента: ни
     чисел SPICE, ни итога LVS до неё не доходили.
   - Ошибка вообще не фиксировалась: в `catch` был только `setError` → тред =
     [user: вопрос, user: «продолжай»]. Модель физически не знала, что
     прошлый заход упал. Это и было «забывает».
   - Пустой assistant-контент — ещё и невалидный ход для части провайдеров
     (Anthropic-стиль) → 400 → 502.
2. **502 «LLM returned empty content»** = выход из тул-цикла без текста
   (`llmGraphAnalysis.ts`): модель 5 раз подряд звала `mmochip_spice_sim`/
   `mmochip_lvs_check` (`MAX_TOOL_ITERS = 4`) и не написала финальный ответ.
   В discuss-пути лестницы токенов не было вообще (фиксированные 32k), тогда
   как в analyze-пути она есть (32k→64k→128k) и ловит свой 502 сам.
3. Уточняющих вопросов в Discuss не было вовсе (механизм `{"questions":[]}` +
   UI ответа есть только в analyze-пути).
4. Тред не обрезался, контекст — полный netlist → промпт рос → модель думала
   дольше → пустой content. Порочный круг.

  и `digest?: string`; новый `AssistantFailedTurn`; `AssistantDiscussResponse`
