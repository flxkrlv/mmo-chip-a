## ELK locked-ноды — эмпирическая проверка (elkjs 0.11.1, node-тесты)

## БАГ-ФИКС: Maximum update depth (zustand v5 + useSyncExternalStore)
- Селектор хука, возвращающий НОВЫЙ объект на каждый вызов (spread в effectivePositions,
  emptyLayout() fallback в lockedMap) => бесконечный re-render при монтировании
  (updateStoreInstance -> forceStoreRerender). Правило: селектор = стабильная ссылка
  (s => s.layouts / s.draft), производные объекты только через useMemo; пустые
  дефолты — module-level константы (EMPTY_POSITIONS / EMPTY_LOCKED).
- imperative effectivePositions(getState()) в колбэках — безопасно, это не селектор.

## Настройки ELK в interactive mode
- Проброшены те же селекторы, что у статики: nodePlacement.strategy (BK/INTERACTIVE/SIMPLE),
  direction (DOWN/UP/LEFT/RIGHT), postCompaction.strategy 0-4 (LUT/scanline/sweep/pocket).
  Цифры compaction elkjs 0.11.1 принимает (проверено node-скриптом, 30 комбинаций OK).
- Автодеградация при падении ELK: compaction requested->0, затем BK->INTERACTIVE->SIMPLE,
  потом grid fallback; результат.applied сообщает фактические настройки, UI показывает
  'degraded: X/cN' в статусе. Смена настроек = полный re-arrange (locked остаются).
- Опции ключи: elk.layered.nodePlacement.strategy / elk.layered.compaction.postCompaction.strategy.

## Выравнивание interactive layout со static (бесшовность)
Разбор vendored netlist2svg.bundle.js:
- Статик передаёт в ELK ТОЛЬКО опции из skin <s:layoutEngine>: betweenLayers=5, nodeNode=35,
  (+ panel: strategy/direction/compaction), portConstraints=FIXED_POS. Остальное — ELK дефолты.
- Классификация пинов: s:position top=input, bottom=output; left/right -> port_directions.
  Следствия: у пассивов B(низ) драйвер, A(верх) потребитель; vcc=A(bottom) драйвер; gnd=A(top)
  СТОК (рельс гонят nmos S и т.п.); driverless-net -> pseudo-driver.
- interactive выровнен: portRole() по этой конвенции (multi-driver->each consumer), спейсинг 5/35,
  убраны мои edgeNode/edgeEdge/padding. Теперь первая раскладка interactive близка к static.

## ОТКАТ: выравнивание static-конвенции (portRole + spacing 5/35)
- Юзер: часть проводов/устройств перестала рисоваться; при drag провода появлялись.
- Вероятная причина: multi-driver конвенция — net где ВСЕ пины output (nmos S x N + vcc,
  без input-пинов) => consumers пусто => 0 рёбер => нет проводов; также риск ELK-краша
  от огромного fan-out (drivers x consumers на VDD-рельсе).
- Откатил: portRole/portDirections export/spacing 5/35. Вернул: driverOf-одиночный драйвер
  (power -> io -> driverOf), spacing 36/56/12/10+padding. ОСТАВЛЕНО: strategy/direction/
  compaction селекторы + автодеградация + applied.
- Урок: перед сменой семантики рёбер проверять кейсы 'все пины одного направления' и
  fan-out на power-рельсах; расхождение со static — известная, отложенная задача.
