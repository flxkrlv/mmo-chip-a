## Wire matching tolerance fix (15:05-15:57)
- **Problem:** `matchWireToPoint()` in `dieWideAnalog.ts` used fixed 10px tolerance. On dense layouts, bus far from contact center failed to match (unconnpin halo), and nearby wires caused shorts.
- **Fix:** Added `contactTolerance(shape)` — computes tolerance proportional to contact size: `size × 0.5` (half the contact dimension). For rect 4×4px → tol = 2px. No margin padding, wire must land on the contact.
- **Pipeline:** `resolveDeviceContacts()` → `termContacts` includes `{x,y,tol}` → caller uses `cp.tol` instead of hardcoded 10. IO pins keep 10px fallback.
- **Rule recorded** in `docs/analog-devices.md` (new "Wire matching tolerance" section).
- Committed as `3e27c25`, branch `analog-re-wip`.

## CellRE: Polyline snap fix + hotkey 'l' (afternoon)
- **Root cause:** In `useLayerPolylineTool.ts`, `addPoint()` snaps to nearest axis using `Math.abs(dx) > Math.abs(dy)` — this only allows horizontal/vertical per segment. First segment horizontal (dx > dy) is correct, but second segment should go vertical to form a U-shape — instead it snaps horizontal again because dx still dominates.
- **Fix (commit `470ed96`):** For subsequent points after the first, snap to the *alternate* axis (whichever wasn't used by the previous segment). If last segment was horizontal, force the next one vertical and vice versa.
- Also hid `W_um` from resistor display, added hotkey `l` for polyline tool via `HOTKEY_CONFIG`, persisted `polylineWidth` across tool switches.
- **Known issue:** Preview in `CellRECanvas.tsx` still only shows one immediate dashed segment — doesn't show the closing segment back to start or the full resistor body fill. Needs separate fix.

## Device contacts → ME1 only + terminal snap halo (16:20-16:45, commit `ff91e52`)
- **Wire matching layer filter:** `matchWireToPoint()` now accepts `allowedLayer?: WireLayer` param. Device contacts filter to `"metal1"` only; IO pins remain unrestricted.
- **Terminal snap halo suppression:** `resolveTerminalSnap()` in `useWireTool.ts` checks `useDieViewerStore.wireLayer` — if not `"metal1"`, returns null (no halo, no auto-snap). Via snap still works regardless.
- **Wire layer palette pruned:** Removed "unk" and "poly" from `WireLayerSelect.tsx` → only m1/m2 shown since device contacts only connect to ME1.
- **W hotkey carousel:** First W → wire tool active + M1; repeat W → M1↔M2 toggle. Other metals reachable via toolbar layer selector.
- **Rule recorded** in `docs/analog-devices.md`.

## E/Q via-insertion hotkeys — design decided (16:45-16:58)
- User chose **option 3**: directional layer cycling
  - **E** = via up to next metal (ME1→ME2, ME2→ME3, ME3→ME4, etc.)
  - **Q** = via down to previous metal (ME2→ME1, ME3→ME2, etc.)
- Metal order array: `["metal1", "metal2"]` (extensible for ME3+)
- Behavior: if at max layer on E → stay; if at min layer on Q → stay
- Implementation plan (not yet coded):
  1. Add `insertDraftPoint()` to `useWireTool.ts` — creates `point_via` at cursor + switches wire layer
  2. E/Q handler in `DieViewerPage.tsx` — get cursor from `cursorLive.get()`, call `insertDraftPoint`, switch layer
  3. Uses existing `point_via` type in `shared/src/types.ts`
- UUID already imported in `DieViewerPage.tsx` — no additional import needed.
