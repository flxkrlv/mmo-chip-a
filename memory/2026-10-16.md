- User choices: writes = markup only (comments + replies, floorplan regions, rulers); per-die mode off / create / edit-own (default off); transport = HTTP at /mcp/<dieId>; MCP undo/redo stored server-side.
- backend/src/api/mcp.ts: hand-rolled JSON-RPC (no SDK dep): initialize (Mcp-Session-Id → clientInfo.name kept in memory for attribution), ping, tools/list, tools/call; notifications → 202; GET/DELETE → 405; foreign Origin → 403 (DNS-rebinding guard); requireAuth (Bearer JWT when JWT_SECRET is set). - backend/src/mcp/mcpState.ts: <projectDir>/mcp.json {mode, owned ids (comments/floorplanRegions/rulers/replies), undo, redo (max 200)}; whole-item before/after snapshots; undo/redo refused when the item no longer matches (key-order-insensitive compare) → human edits are never clobbered.

MCP items: authorId/createdBy "mcp", name "MCP · <client>".
- api/tiles.ts: serveCrop body extracted into exported renderDieCrop (reused by get_die_image). overlayImages listManifests exported.
- Frontend: InspectorTab "mcp" + McpPanel (endpoint URL, `claude mcp add` line, JSON config incl. Bearer token if logged in; mode chips; history with Undo/Redo, refreshed via annotation WS events). vite proxy /mcp → :3001.

## Claude Desktop only exposed the manifest's 13 tools
- Symptom: MCP agent in Claude Desktop saw only the original 13 tools after wire / full-edit / render tools were added; server listMcpTools() returns 22.
- Cause (inferred from the exact 13 = installed 0.1.0 manifest tool list): manifest lacked `"tools_generated": true`, so Claude Desktop goes by the declared tools. Added it, bumped to 0.3.1, rebuilt dist/mmo-chip.mcpb. User must reinstall the extension. Lesson: my earlier "existing install gets new tools from the server" was wrong — after adding tools, rebuild + reinstall the .mcpb.
