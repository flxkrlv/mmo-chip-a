# Folder-проекты (mmo-chip-a) — краткое резюме

## Что это
Возможность хранить проект микросхемы НЕ в управляемом хранилище приложения
(<dataRoot>/dies/<dieId>), а в произвольной папке пользователя рядом с его
рабочими файлами (USB, Dropbox, D:\SyncStore\...). Папка — самодостаточный
источник истины, помечена файлом project.json; копирование папки переносит
весь проект без экспорта/импорта ZIP.

Два режима проекта: managed (как раньше, дефолт) и folder (новый).
Активируется только когда пользователь явно открывает/создаёт проект в папке.

## Ключевые точки в коде
- backend/src/projectLayout.ts — резолвер «где живёт проект»:
  resolveProjectDir(Sync), prepareFolderProject, registerFolderShortcut,
  read/writeProjectManifest. Управляемые пути: dies/<id>, overlay-images/<id>.
- backend/src/api/fs.ts — GET /api/fs/browse (серверный браузер папок),
  POST /api/dies/open-folder, POST /api/dies/:dieId/relocate
  (тело: { "path": "<newdir>" } — поле именно path).
- backend/src/api/dies.ts — POST /api/dies/import принимает form-поле
  targetFolder; в списках отдаёт location/available/folderPath.
- Все per-die пути (store, tiles, overlayImages, analogExport, mlExport,
  tileScheduler, importer) идут через резолвер.
- Локальный реестр ярлыков: <dataRoot>/folder-projects.json (НЕ источник истины).

## Правила создания проекта в папке
- Папка должна существовать → иначе 400 folder_missing.
- Папка не должна содержать project.json → иначе 409 project_exists.
- Папка должна быть ПОЛНОСТЬЮ ПУСТОЙ → 409 folder_not_empty
  (commit 3932d7f; раньше блокировались только артефакты проекта).
  Цель: никогда не затирать чужой проект и не подмешивать посторонние файлы.
- Импорт асинхронный: 202 + import-job; переезд папки между дисками
  поддержан (fallback copy+rm при EXDEV, commit 7a03478).

## Регрессии
Нет. Управляемый режим работает ровно как раньше. Коррекции ради точного
соответствия старому поведению: deleteDieRecord НЕ удаляет overlay-images/<id>;
listDieRecords глотает ошибку чтения только для folder-проектов.

## Уроки (CRLF!)
- Все файлы репы в CRLF — НИКОГДА не править их через edit_existing_file/lossy-редактор.
- Единый инструмент tools/crlf-patch.mjs (import patchFile): read utf8 ->
  .replace(/\r\n/g,"\n") -> защищённая замена LF-якоря (includes()+уникальность,
  throw БЕЗ записи) -> .replace(/\n/g,"\r\n"). Идемпотентно по маркеру `id`.
- Разовые tools/patch-*.mjs (35 шт.) УДАЛЕНЫ из рабочей папки (git rm, история
  сохранена) — их результат уже в коммитах; на новой машине не нужны.
- Новые файлы: create_new_file/shell пишут LF -> нормализовать в CRLF.
- После правки: git diff --stat + typecheck.
