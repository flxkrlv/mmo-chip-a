# Folder-проекты (mmo-chip-a) — краткое резюме

## Что это
Возможность хранить проект микросхемы НЕ в управляемом хранилище приложения
(<dataRoot>/dies/<dieId>), а в произвольной папке пользователя рядом с его
рабочими файлами (USB, Dropbox, D:\SyncStore\...). Папка — самодостаточный
источник истины, помечена файлом project.json; копирование папки переносит
весь проект без экспорта/импорта ZIP.

Два режима проекта: managed (как раньше, дефолт) и folder (новый).
Активируется только когда пользователь явно открывает/создаёт проект в папке.

## Ключевые точки в коде
- backend/src/projectLayout.ts — резолвер «где живёт проект»:
  resolveProjectDir(Sync), prepareFolderProject, registerFolderShortcut,
  read/writeProjectManifest. Управляемые пути: dies/<id>, overlay-images/<id>.
- backend/src/api/fs.ts — GET /api/fs/browse (серверный браузер папок),
  POST /api/dies/open-folder, POST /api/dies/:dieId/relocate
  (тело: { "path": "<newdir>" } — поле именно path).
- backend/src/api/dies.ts — POST /api/dies/import принимает form-поле
  targetFolder; в списках отдаёт location/available/folderPath.
- Все per-die пути (store, tiles, overlayImages, analogExport, mlExport,
  tileScheduler, importer) идут через резолвер.
- Локальный реестр ярлыков: <dataRoot>/folder-projects.json (НЕ источник истины).

## Правила создания проекта в папке
- Папка должна существовать → иначе 400 folder_missing.
- Папка не должна содержать project.json → иначе 409 project_exists.
- Папка должна быть ПОЛНОСТЬЮ ПУСТОЙ → 409 folder_not_empty
  (commit 3932d7f; раньше блокировались только артефакты проекта).
  Цель: никогда не затирать чужой проект и не подмешивать посторонние файлы.
- Импорт асинхронный: 202 + import-job; переезд папки между дисками
  поддержан (fallback copy+rm при EXDEV, commit 7a03478).

## Фикс: delete/reopen и перемещённая папка (после коммитов ниже)

3. Перемещённая папка -> проект ИСЧЕЗАЛ из Library (listDieRecords глотал

## Уроки (CRLF!)
- Все файлы репы в CRLF — НИКОГДА не править их через edit_existing_file/lossy-редактор.
- Единый инструмент tools/crlf-patch.mjs (import patchFile): read utf8 ->
  .replace(/\r\n/g,"\n") -> защищённая замена LF-якоря (includes()+уникальность,
  throw БЕЗ записи) -> .replace(/\n/g,"\r\n"). Идемпотентно по маркеру `id`.
- Разовые tools/patch-*.mjs (35 шт.) УДАЛЕНЫ из рабочей папки (git rm, история

## Фикс: два одинаковых folder-проекта / повторное открытие папки

  открытие возвращает существующий id; idsInUse включает ВСЕ shortcut id;
  metadata.json переписывается ПО МЕСТУ с новым id (и дедуплицированным именем

## Per-project имена analog-девайсов (жёсткая привязка)
- Проблема: имена жили в глобальном localStorage (mmo-chip-device-registry /
  mmo-chip-analog-names); при создании проекта из ZIP глобальный реестр
  перезаписывался -> имена «плыли». Для folder-проектов имена не лежали в папке.
- Решение (по выбору пользователя): детерминированный id из shape-id +
  новый analog-devices.json per-project; старые имена НЕ мигрируются.
- Идентичность: `_deviceAnchor` (frontend/src/lib/extraction/simpleAnalog.ts):
  marker:<markerShapeId>; mos:<wellId>:<diffId>:<gateId>;
  geores:<bodyIds>:<contactIds>. В dieWideAnalog.ts -> `_templateId`,
  `_instanceId = <templateId>@<cellInstanceId>`. Стабильно при сдвиге слоёв,
  ZIP round-trip, переоткрытии.
- Хранение: analog-devices.json {version:1, devices:{instanceId:name}} в папке
  проекта / <dataRoot>/dies/<dieId>/. Backend: GET/POST
  /api/dies/:dieId/analog-devices (api/analogExport.ts) + включён в ZIP
  export/import (api/projectIO.ts) + pruneProjectArtefacts.
- Frontend: state/analogDeviceNames.ts — загрузка/сохранение, скоуп на активный
  проект (setActiveProject), debounce save 250ms, флаг loaded (пока не загружено
  — автоимена не сохраняются, чтобы медленная загрузка не затирала имена).
  setActiveProject(dieId) вызывается в DieViewerPage и AnalogNetlistPage.
- Нейминг: assignStableInstanceNames читает/пишет store по _instanceId; счётчик
  сеется по ВСЕМ именам (включая удалённые девайсы, записи не прунятся) ->
  имена уникальны и НЕ переиспользуются. rename/validate переведены на
  instanceId (DeviceInspector, AnalogNetlistPage). Глобальный deviceRegistry

- Кэш _fullResult в dieWideAnalog теперь включает proj (active dieId) и
  nv (getAnalogNamesVersion) — иначе копии/переименования возвращали бы
  закэшированные имена. Реактивность: useAnalogNamesVersion подписан в

  analog-devices.json) 4/4; fs.test.ts 7/7; frontend 129/129.
- Известное допущение: имена грузятся async при открытии проекта; до загрузки

## Fix: удалённый analog-девайс освобождает своё имя
- Проблема: analog-devices.json никогда не прунился — счётчик автоимён сеялся по
  ВСЕМ именам (включая удалённые девайсы), а validateProjectDeviceName блокировал
  имя, пока запись жива. После удаления девайса его имя нельзя было присвоить
  другому (ни автоматически, ни вручную).
- Решение: имена живых девайсов остаются жёстко привязанными; имена исчезнувших
  освобождаются. assignStableInstanceNames (frontend/src/api/dieWideAnalog.ts)
  строит множество live `_instanceId` и вызывает новый
  syncLiveProjectDevices(liveInstanceIds) (frontend/src/state/analogDeviceNames.ts),
  который удаляет из стора записи отсутствующих девайсов (no-op, пока стор не
  загружен). Авто-нумерация перешла с max+1 на «минимальный свободный» номер
  префикса (collectUsedNameNumbers + nextFreeInstanceName) — освобождённый номер
  переиспользуется. Ручной rename проходит, т.к. записи мертвеца в сторе нет.
- Тесты: +5 analogDeviceNames.test.ts, +3 dieWideAnalog.test.ts (мок backend-стора
