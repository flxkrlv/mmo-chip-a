## Hierarchical netlist: only 1 block found bug

- User reported hierarchical netlist only generates 1 subcircuit (sth_strange) instead of 2 expected (sth_strange + diffp)
- Top-level had no flat devices and no ports (only VDD/GND) — meaning all 4 devices were consumed by regions but only 1 subcircuit appeared
- Root cause investigation:

### Bugs found & fixed:

1. **`kind: "poly"` vs `"polygon"` typo** — In `DieViewerPage.tsx:2133`, polygon regions saved with `kind: "poly"` but type definition expects `"polygon"`. Fixed: now saves `kind: "polygon"`.

2. **No cache invalidation after floorplan save** — `apiPut` for floorplan region did not invalidate the React Query `useAnnotations` cache. When navigating from DieViewer to AnalogNetlistPage, stale annotations (without the new region) could be served. Fixed: added `queryClient.invalidateQueries({ queryKey: ["annotations", dieId] })` after both rect and poly region creation.

3. **FloorplanOverlay backward compat** — SVG rendering checked `region.kind === "poly"` but new data will have `"polygon"`. Fixed to accept both.

### Actual root cause (DEBUG CONFIRMED):
**All 4 MOS transistors share the same `id: "mos_well_nwell_1"`** — they're cloned from the same cell-type definition in `collectDieWideAnalogDevices`. The `assignedDevices` Set used `d.id` as key, which collapsed all 4 to 1 entry. Two bugs cascaded:

1. **Partition bug**: first device whose center falls inside a region gets assigned; all others with duplicate id are SKIPPED → only 1 device per subcircuit
2. **`detectBoundaryNets` bug**: same duplicate-id issue — `insideIds` contained 1 id, so ALL devices appeared as boundary nets

### Fix implemented:
- Changed the key from `d.id` (shared cell-type id) to a **composite key** `d.id + ":" + index` for deduplication in `assignedDevices` set
- Found the collector function at `dieWideAnalog.ts` returning devices with unique `id` per device type, so only 4 clones in test case. Fixed the partition logic to use array index or composite key instead of id-based dedup.
- Also added `id_to_devices_map` approach inside `partitionIntoRegions` for proper many-to-one tracking instead of one-to-one
