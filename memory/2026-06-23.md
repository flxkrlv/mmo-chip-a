1. **Partition bug**: first device whose center falls inside a region gets assigned; all others with duplicate id are SKIPPED → only 1 device per subcircuit
2. **`detectBoundaryNets` bug**: same duplicate-id issue — `insideIds` contained 1 id, so ALL devices appeared as boundary nets

### Fix implemented:

- Found the collector function at `dieWideAnalog.ts` returning devices with unique `id` per device type, so only 4 clones in test case. Fixed the partition logic to use array index or composite key instead of id-based dedup.
- Also added `id_to_devices_map` approach inside `partitionIntoRegions` for proper many-to-one tracking instead of one-to-one

## Option B: Global net rename on die via port aliases (15:45)

User confirmed they want Option B: setting a port alias in the floorplan region popover should **rename the annotation net on the die itself** (not just in the netlist generator output).

### Implementation

**Challenge:** FloorplanRegion.portAliases uses numerical netIds (100, 101...) but annotation nets use UUIDs ("net_abc123"). Need reverse-map from `collectDieWideAnalogDevices`'s `netIdMap` (UUID→numerical) to get numerical→UUID mapping.

**Solution in FloorplanRegionPopover.tsx:**

1. On save, builds reverse map (numerical netId → UUID) from `collectDieWideAnalogDevices().netIdMap`
2. For each new/changed alias → calls `PUT /api/dies/:dieId/nets/:uuid` to rename the annotation net on the server
3. For each removed alias → reverts to the original net name (stored in `originalNetNamesRef` on first load)
4. All renames fire in parallel via `Promise.all`

**Design decisions:**
- Used existing `registerCollectionRoutes` net endpoint (`PUT /api/dies/:dieId/nets/:netId`) — already handles individual net updates on the backend
- Original names stored in a ref to support reverting when alias is cleared (not persisted — reconstructs on next load)
- Skip nets where alias hasn't actually changed (compare old vs new aliases)
