## Metal connectivity (mergeMetalConnectedTerminals) — done and pushed

### What was implemented
- **GUI warning**: If Clipper2 is not loaded, a warning is shown on AnalogNetlistPage
- **poly gate grouping**: Connected-component grouping of poly shapes via Clipper2 polygon intersection + UnionFind. Shared poly buses now get the same gate netId across all MOS devices.
- **Overlay fix**: Gate terminal shapeIds now include all poly shapes from the same gate net component (not just the ones cutting diffusion), so the die viewer overlay highlights shared poly buses too.
- **cellNetCache** (die-level): Same cell-level netId → same die-level netId in SPICE
- **mergeMetalConnectedTerminals** (cell-level metal connectivity): UnionFind over metal1 + metal2 + via1 + contact shapes. D/S terminals from different devices sharing the same metal component get one cell-level netId.

### How mergeMetalConnectedTerminals works
- Collects metal1, metal2, via1, contact shapes from cell layers
- UnionFind: same-layer intersection → union; contact↔ME1 overlap → union; via1↔ME1↔ME2 → union
- For each terminal: find contacts overlapping its region → UF root → metal component
- **shapeKey dedup rule**: Within same device and UF root, terminals with identical shapeId sets (e.g., resistor PLUS/MINUS both having all contactIds) → only first gets merged netId, second keeps original (die-level round-robin resolves it)
- Works for all device types: MOS (D, S), BJT (C, B, E), resistor/capacitor/diode (PLUS, MINUS)

### Current limitations
- Single-finger MOS: D and S share [bodyId] → same shapeKey → only D merged across devices, S stays separate
- Resistor/capacitor/diode-marker: PLUS and MINUS share all contactIds → same shapeKey → only PLUS merged, MINUS separate
- Fix suggested: split contacts between terminals at creation time (half/half) → different shapeIds → full merge without shapeKey dedup

## mergeMetalConnectedTerminals — extended to all device types (later in session)

### Key discovery
- 2-terminal devices (resistor, capacitor, diode-marker) give PLUS and MINUS the **same** shapeIds (all contacts in bbox).
- MOS single-finger D/S also share shapeIds `[bodyId]`.

### ShapeKey dedup approach
- Removed MOS-only filter → all device types participate
- MOS: skip G (gate, handled by polyGateNetMap) and B (bulk, sentinel -2)
- Non-MOS: all terminals participate
- Within a UF root: first terminal per (devId, shapeKey) gets merged netId; subsequent terminals with same (devId, shapeKey) keep original netIds
- Cleaned up duplicate code (removed dead rootToTerms path, kept only grouped path)

### Behavioral change
- Single-finger MOS: D and S stay separate (same shapeKey `[bodyId]` — within-device skip)
- Two-finger/etc MOS: fine — different bodyIds for different diffusions
- Resistor: PLUS merged across devices, MINUS kept separate via shapeKey skip

### Fix recommended for future
- Split contacts between terminals at creation time (half/half) → different shapeIds sets → shapeKey dedup won't fire → full merge without hack

## Resistor contact splitting — reworked (later in session)

### Problem
The original approach (`body INTERACT contact`) failed because resistor contacts do not physically intersect the body polygon — they're connected through ME1.

### Solution: body→ME1→contact chain
1. Find ME1 polygons that intersect the body → `bodyHits`
2. UnionFind by bodyHits polygon intersection → connected ME1 groups
3. Each ME1 group: find contacts inside those ME1 polygons → those contacts belong to one terminal (PLUS or MINUS)
4. ShapeIds for PLUS = contacts from ME1 group 0; MINUS = contacts from ME1 group 1
5. **Fallback** (1 or 0 ME1 groups): all contacts to both terminals (pre-existing behavior, die-level resolves it)

### Debug logging
- `[analog] ME1[${i}] hits body, ctIds=[...]`
- `[analog] ME1 groups: N`

### Verified working
- User confirmed: "да, работает" (yes, it works)
- The CONNECT layers confirm ME1→VIA1→ME2 connectivity chain works correctly
